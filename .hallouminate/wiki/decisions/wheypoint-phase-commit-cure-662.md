# Wheypoint phase-commit cure decisions (PR #662)

Recorded by the `/affinage` → `/cure` chain on PR #662 (`feat/wheypoint-phase-rehydration`). These are the review findings that changed the design, plus one open decision.

## Decisions

- **One repository-root source.** `paths.resolve_repo_root(root)` (git toplevel, else cwd, resolved) is the only way the kernel derives "the repository root". `lint.lint_work`, `resolve.resolve()`, `commit._digest_root`, and `phase_commit.commit_phase_revision` all call it. Before this, the reader anchored to bare cwd while the writer digested against the explicit artifact root, so `wheypoint-resolve` from a subdirectory produced a gating `stale-artifact-link`.
- **One grounded-entry grammar.** `shared/wheypoint/grounded.py` owns `parse_grounded_entry`, `validate_grounded`, `GroundedEntryError`, `MAX_GROUNDED_ENTRIES`. `lint_freshness.grounded_path_findings` and `write_handoff_artifact` import it directly (the `phase_commit` re-exports were dropped in the second cure). The module deliberately imports nothing from the kernel so it can sit under both `lint` and `phase_commit` without the `lint → phase_commit → commit → lint` cycle basedpyright rejects.
- **`error` is a real resolve outcome.** `wheypoint-resolve` prints the full payload with `outcome: "error"`, `ok: false`, `dispatchable: false`, plus `findings`/`searched`/`source`, and exits `EXIT_REFUSED`. The bare `{ok, command, error}` envelope is reserved for usage and internal errors. `shared/wheypoint/resolve_cli.py` is the single owner of the payload projection (`resolve_payload`, `resolve_status`, `BadUsage`, `Parser`, `EXIT_*`, `emit`/`refuse`); `skills/wheypoint/wheypoint.py::_run_resolve` imports them and keeps only `--legacy`. (`Refusal` was removed in the second cure; the payload is returned for every outcome and `resolve_status` maps `error` to `EXIT_REFUSED`.)
- **Read-only git guard covers `run_git`.** `tests/wheypoint/python/test_projection.py` scans both literal `["git", ...]` argv and `run_git([...])` / `_run_git_ok([...])` calls. Kernel git calls go through `easy_cheese.shared.git_utils.run_git`; add new invocations to `READ_ONLY_GIT` there.
- **Chain-phase write boundary.** `write-handoff-artifact` accepts `--corpus-root`, opens one `WorkStore` for the pre-read and the commit, rejects `--grounded` on non-chain phases, and reports wheypoint failures as `wheypoint: <TypeName>: <message>`; a traceback prints only for unexpected types or under `EASY_CHEESE_DEBUG`/`CHEESE_DEBUG`. A commit failure after the artifact landed exits `5` with `wheypoint: artifact-orphaned <path>` (see the second cure below).
- **Retry is observable.** `commit_phase_revision` returns `CommitOutcome(result, retried)` and writes one stderr line naming the refreshed parent revision before the single retry.
- **Lineage checks read receipts only.** `WorkStore.receipt_revisions()` parses revision JSON without reading or hashing projections; `commit._check_lineage` uses it, so a commit no longer rescans every projection in the store.

## Open decision

- **Artifact-before-commit ordering.** `write_artifact` still `os.replace`s the phase artifact before `commit_phase_revision`; `test_commit_failure_keeps_written_artifact` locks that. A deterministic commit failure therefore leaves an artifact whose digest no longer matches the last revision's link, and the next resolve gates on `stale-artifact-link`. Options: commit first against the staged tmp digest, restore the prior bytes on failure, or make that link non-gating when the artifact is newer than the revision. Not changed in #662; author's call.

## Follow-up

- Every skill bundle carries the whole `easy_cheese.shared` tree, so the kernel move added ~190 KB to each of 13 `.pyz` files. Splitting the kernel into its own wheel for the chain skills only is a sprawling change left for a later PR.

## Second cure (seven-lens /age, 57 findings, `all-medium, cheap`)

- **Producer-owned write boundary.** `phase_commit.commit_phase_revision(*, work_id, phase, next_skill, artifact, orientation, grounded, store, write_contents, root=None, provenance=None) -> CommitOutcome` owns validate -> open -> read -> genesis guard -> provenance -> `write_contents()` -> commit -> one retry that re-runs the genesis guard on the refreshed record. `write_handoff_artifact._wheypoint_revision` is a thin adapter. Rejected alternative: a caller-side preflight/commit split (Age finding 23); it would have kept two owners for one invariant.
- **Writer exit codes are a contract.** `2` caller usage (bad `--grounded`, genesis without one; nothing written), `4` `EXIT_WHEYPOINT` (kernel failure before the write), `5` `EXIT_ARTIFACT_ORPHANED` (artifact on disk, no revision; stderr `wheypoint: artifact-orphaned <path>`). Constants live in `write_handoff_artifact`, their only consumer, not in `phase_commit` or `shared/cli.py`; `phase_commit` classifies its own failures instead (`PhaseCommitRefusal` -> `2`, `ArtifactOrphaned` -> `5`, anything else -> `4`) and prints the repo-relative artifact path. Every `wheypoint:`-tagged line is one plain-ASCII line a caller on any host can grep; refusals (exit `2`/`4`) surface through the shared CLI as `ERROR: <message>`.
- **Env provenance is validated at the boundary.** `EASY_CHEESE_SESSION_ID`/`CHEESE_SESSION_ID` must match the schema identifier regex and `*_CAPTURED_AT` must round-trip `%Y-%m-%dT%H:%M:%SZ`; `*_HARNESS` must be a single line; a miss falls through to the alias and, when neither validates, drops the value with one `wheypoint: ignoring <ENV>` line instead of failing after the artifact write. `checkpoint.TIMESTAMP_FORMAT` is the one declaration of that format. No harness-specific name is ever read.
- **Only the current phase artifact is re-pinned.** `_phase_links(root, work_id, phase)` returns one link; sibling links carry forward with their original digest so drift stays detectable.
- **Writer and readers share one root.** `_cmd_write` anchors at `paths.resolve_repo_root(--root)`; a run from a subdirectory no longer strands the artifact under `<subdir>/.cheese/`.
- **Read path.** `lint_work` walks `WorkStore.survey_receipts()` and reads only the current projection; `preloaded_record`/`recover(record=)` were removed because they skipped the raw schema stamp and killed the `runtime-behind` guard on the slug path (the saved read was one `record.json`). `lint` cannot reach zero projection reads: `_lint_current_projection` sources every `PROJECTION_*` finding.
- **Module layout.** `lint_freshness.py` holds the git-staleness, artifact-link, and grounded-path checks; `lint_types.py` holds `LintCode`/`LintFinding`/`ADVISORY_CODES`/`gates_continuation` so `lint <-> lint_freshness` stays acyclic (basedpyright `reportImportCycles`). `grounded.resolve_within` is the one containment predicate for writer and linter.
- **Grounded grammar.** The range anchors on the last `#` (a `#` in a file name is legal); `PR#<n>` and URL pointers in `working_context` are exempt from the grounded grammar in lint, matching `intent-contract.md`.
- **Resolve CLI.** `--corpus-root` on both resolve entry points; a ref that passes `_IDENTIFIER_RE` but fails `KEBAB_SLUG` resolves `not-found`; corpus directories failing `_WORK_ID_RE` are skipped; `Refusal` is gone (`resolve_status(payload)` picks the exit code); `wheypoint.py` imports its CLI helpers from `resolve_cli`.
- **Deferred.** Age finding 25 (`write_artifact` -> `HandoffSlug`) spills into `tests/schemas/python/test_handback_status_contract.py`; three moderate-cost lows (Phase-entry prose dedup across five SKILL.md files, `--grounded`/`working_context` naming, a CHAIN_PHASES registration test). Issue #654 ask 4 (compaction hook) is deferred until a host-neutral trigger exists; the PR now says "Refs #654".
- **Coder sizing lesson.** Every cure coder that took more than ~8 findings or two 500-line files hit its context ceiling before it ran a gate. Split by file cluster, cap at ~6 findings per dispatch, and make "gate + commit" its own dispatch when the edit pass is large.

## Third pass (re-age of the cure, 33 findings, `all-medium, cheap`)

- **Refuse before the write, always.** `commit_phase_revision` validates the slug (`paths.validate_slug`) and probe-binds the `CheckpointIntent` before `write_contents()`; `write_artifact` rejects a non-kebab `--slug` for every phase at the argv boundary. Before this, `my_slug` or a 2001-char `--orientation` passed every pre-write guard, wrote the artifact, and then failed inside `_phase_links`/`CheckpointIntent` as exit `5` with an orphaned file. Rule: anything that can still refuse the input runs before the artifact `os.replace`.
- **Bundle membership is derived, not listed.** `tests/python/test_build_pyz_tree_staging.py` computes the kernel module set from `src/easy_cheese/shared/wheypoint/*.py` and asserts set equality against each chain bundle; a hand-maintained list had silently dropped five modules.
- **`lint` has no `__all__`.** The `lint_types` vocabulary is re-exported with the explicit `X as X` form; `resolve.py`/`commit.py` import `lint_freshness` directly (the pass-through delegators are gone) and `resolve.py` takes `LintFinding`/`gates_continuation` from `lint_types`.
- **One receipt reader.** `storage._structure_receipt` owns the identity checks and skip strings for both `revisions()` and `survey_receipts()`; projection stems are listed once per scan. `grounded.resolve_within(path_text, resolved_root) -> GroundedPathIssue | None`; `resolve._slug_matches -> tuple[str, ...]`.
- **`git-unavailable` is one `key=value` line per `lint_work`** (`lint_freshness.git_warnings_once` latch); `--corpus-root` and `--legacy` are mutually exclusive in the resolve parser.
- **Open (deferred to a round that owns `storage.py`).** `lint_work` walks `survey.revisions` built with the projection-present filter, so an ancestor with a deleted projection gates `PARENT_UNRESOLVED` while `commit._check_lineage` (receipts only) accepts the chain; the docstring now states the stricter reader behaviour. Switching the walk to receipts-only needs a second survey shape without a second scan.
- **Deferred lows.** Round-1 #25/#30/#52/#53 stand; round-2 low 32 (moving the coder-sizing lesson off this page) is declined: process knowledge belongs on the wiki by repository rule.
