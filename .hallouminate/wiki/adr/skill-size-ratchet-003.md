# ADR: Ratchet skill size and reference structure against a recorded baseline

The gate grandfathers today's over-budget skills and structural violations at their recorded values, blocks any growth or new violation, and holds new skills to the full budget.

## Decision record

### ADR-003: Grandfathered ratchet over a flat cap [status: accepted]

- **Context:** Six of 16 skills already exceed the 5k-token budget, 20 reference files violate the one-level-deep rule, and 6 reference files are orphaned. A flat cap turns CI red on day one, which gets the gate disabled rather than obeyed. A cap set high enough to pass today (above `cook`'s ~9,250) would never fire. The repo already resolved this tension once for content duplication — see [[skill-overlap-ratchet-004]], which blocks new findings against a reviewed baseline rather than enforcing an aggregate budget — and the same reasoning applies to size.
- **Decision:** Record per-skill budgets and per-violation allowlists in a checked-in `.github/skill-budgets.json`. A skill at or under the token target (3,600 — see [[skill-size-ratchet-001]] ADR-001a) must stay under it. A skill over the target is pinned at its recorded value and may only shrink. A skill absent from the file is new and must meet the full target. Nested-reference and orphaned-reference violations are allowlisted by path; any new one fails. Regeneration is an explicit `just update-skill-budgets`, never automatic, so every loosening is a reviewable line in the diff.
- **Alternatives:** Flat 5k cap with an exemption list; a percentage slack band above each recorded value; advisory warnings with no failure; fixing all 26 existing violations first and then enforcing flat.
- **Consequences:** CI is green today and the tree can only improve — the six over-budget skills are frozen and every new skill is born compliant. Legitimate growth in an existing skill requires deliberately regenerating the baseline, which is the intended friction. The gate never forces the underlying cleanup, so `affinage` (8k tokens, zero reference files) stays as debt until someone splits it. Shrinking does not auto-tighten the recorded budget; the ratchet only re-pins on an explicit regeneration.

### ADR-003a: `.agents/skills/` is in scope for frontmatter and size, out of scope for reference topology [status: accepted, amends ADR-003]

- **Context:** `validate_skills.py` discovered skills by rglobbing for `SKILL.md` and dropping any path containing a dot-prefixed part — which correctly skips `.github/`, `.cache/`, and `.claude/`, but also made the two repo-local skills under `.agents/skills/` invisible. They had no frontmatter validation, no `name`/directory match check, no description cap, and no size budget. That gap let a real defect ship: a directory rename left `name: pythonic` stale against its new parent directory for a day with nothing to catch it.
- **Decision:** Keep the dot filter and add a narrow allowance for `.agents/skills/` only, via an `_under_agents_skills()` predicate OR'd into the skip. The path-shape check accepts `[".agents", "skills", <name>, "SKILL.md"]` in addition to `["skills", <name>, "SKILL.md"]`; anything deeper or elsewhere under `.agents/` falls back to the pre-existing behaviour, so `.agents/foo/SKILL.md` stays silently skipped exactly as `.cache/...` does. Frontmatter rules and the size ratchet apply — these are real skills whose bodies cost context on trigger — so `compute_budgets()` measures both trees and the budget file gained `python-authoring` (1,544) and `skill-authoring` (1,817), both well under target. The nested-reference and orphaned-reference checks stay anchored to `skills/` only: they describe the shipped cross-skill reference topology, which repo-local dev skills are not part of.
- **Alternatives:** Drop the dot filter entirely (would pull in `.github/`, `.cache/`, `.claude/`); keep `.agents/` unvalidated and rely on review; mirror the two skills into `skills/` so the existing discovery finds them (would ship contributor tooling, the exact thing [[cheese-kernel-shared-refs-001]] ADR-001a moved out).
- **Consequences:** The validator reports 18 files rather than 16. Markdownlint was widened in the same pass (`justfile` and the CI lint job now glob `.agents/**/*.md`), so both gaps recorded as accepted costs in [[cheese-kernel-shared-refs-001]] ADR-001a are now closed. The nested-reference allowlist dropped from 20 to 19 entries as a side effect of unlinking `skill-authoring.md`: `cook-discipline.md`'s only nested link was that pointer, so it left the list entirely, while `cure-discipline.md` retains a separate nested link to `code-intelligence-routing.md`. That is the ratchet tightening on real cleanup, which is the intended direction.
