# ADR: shared docs live in the cheese skill's references dir, cited sibling-relative

### ADR-001: `skills/cheese/references/` is the home for cross-skill shared docs  [status: accepted]

- **Context:** Both install paths (`npx skills add` — SKILL.md-dir discovery; `scripts/install.sh` — `contents/skills` fetch) drop repo-root `shared/`, so every installed skill carried dangling references to handoff-gate.md, formatting.md, harness-portability.md, optional-plugins.md, semantic-backends.md, skill-authoring.md. The Agent Skills spec has no cross-skill sharing primitive; the community norm is duplication (research: `.cheese/research/shared-skill-content/`).
- **Decision:** Move the six shared docs into `skills/cheese/references/` (cheese = the always-installed entry-point router, present in `EC_FALLBACK_SKILLS`). Every reference — markdown link *and* prose — uses the relative-from-current-file form (`../cheese/references/<f>.md` from a SKILL.md; `../../cheese/references/<f>.md` from a references file), which resolves identically in the repo tree and every sibling-installed tree.
- **Alternatives:** (a) Build-step inlining per skill (the `.pyz` pattern for markdown) — rejected: N skills load N byte-identical copies into context; a single path is read once per session. (b) New dedicated `shared`/`rind` skill — works, but adds a skill-list entry and a second always-install dependency; cheese already is one. (c) Plugin packaging (`.claude-plugin/`) — preserves top-level dirs but abandons `npx skills` compatibility and rests on an unverified `${CLAUDE_PLUGIN_ROOT}`-in-SKILL.md mechanism (anthropics/claude-code#9354). (d) Patch installers — impossible for the upstream vercel-labs CLI.
- **Consequences:** Zero installer/build changes; shared docs enter the `skills/**/*.md` lint glob (closing the unlinted-`shared/` hole); `gen_docs.py`'s dedicated shared section retires. Cost: a `--skill <subset>` install without `cheese` still dangles (accepted, documented); repo-root `shared/` keeps only `scripts/`.


### ADR-001a: `skill-authoring.md` leaves for `.agents/` — it was a passenger, not a shared runtime contract [status: accepted, amends ADR-001]

- **Context:** ADR-001's batch move was location-driven: it emptied repo-root `shared/` because neither install path preserves that directory. `skill-authoring.md` sat in `shared/` on that day, so it moved with the rest — git records it as `R100` with a zero-line diff (`f458a439`, PR #242), never a per-file judgement that it belonged inside a shipped skill. Inbound-link counts show it never behaved like the rest of the kernel: `code-intelligence-routing.md` 26, `agent-resolution.md` 13, `handoff-gate.md` / `formatting.md` / `ask-user-question.md` 12 each, `optional-plugins.md` / `harness-portability.md` 10 each — against 3 for `skill-authoring.md`. All three cited it for the Iron Law / Red Flags / Rationalization-table template alone, and both discipline files already carried their own filled-in copies of those sections, so the links were authoring meta-commentary, not runtime dependencies. Its other five sections (CSO description rule, size budget, authoring checklist, pressure-test gate, `disable-model-invocation` note) had zero runtime consumers.
- **Decision:** Relocate to `.agents/skills/skill-authoring/SKILL.md` and delete all three inbound links rather than retarget them. Contributor-facing authoring guidance does not ship. `.gitignore` gains `!.agents/skills/skill-authoring/` because `.agents/skills/*` is an explicit allowlist — without that line the file is silently untracked. `_MOVED_DOC_NAMES` / `MOVED_DOC_NAMES` drop the entry (no longer a shipped kernel doc); `_FORMER_SHARED_NAMES` keeps it, since a regressed `shared/skill-authoring.md` reference would still be wrong.
- **Alternatives:** Keep it in cheese (status quo — ships contributor docs to every user); move it and retarget the three links (leaves shipped skills depending on an unshipped file); move it and inline the Iron Law template into both discipline files (the duplication ADR-001 explicitly rejected for the kernel).
- **Consequences:** ADR-001's core decision stands unchanged for the genuine shared kernel — this amendment narrows its membership by one, it does not reverse it. Installed trees no longer carry authoring guidance nobody executes. Cost: `.agents/**` sits outside the markdownlint glob (`skills/**/*.md`, `*.md`) and outside `validate_skills.py`'s `skills/`-anchored discovery, so the relocated file loses both lint and frontmatter validation. Accepted and recorded here; widening either glob to cover `.agents/` is a separate change.
