# ADR — html-report-renderer-001

### ADR-001: Keep the closed-subset Markdown renderer in `shared/html_report.py`  [status: accepted]

- **Context:** `src/easy_cheese/shared/html_report.py` hand-rolls a two-pass Markdown→HTML converter, and a NIH audit (#517) asked whether a maintained renderer (`markdown`, `mistune`, `markdown-it-py`) should replace it. Three repo constraints bound the answer: the `.pyz` bundle doctrine admits only pure-Python, zip-importable dependencies; `build-pyz.yml` diffs committed bundles, so bundle bytes must stay reproducible; and the renderer's input is not arbitrary user Markdown — it is report artifacts our own skills author against the subset documented in the module docstring.
- **Decision:** Keep the custom renderer and treat its closed subset as an intentional, tested contract. The subset boundary and the "why not a library" rationale live in the module docstring; `tests/shared/python/test_html_report.py::TestClosedSubsetContract` pins the security-relevant behaviour (raw HTML is escaped, never passed through) and the documented gaps (setext headings, reference links, images, strikethrough, definition lists) so an accidental drift toward CommonMark shows up as a test failure rather than a silent behaviour change.
- **Alternatives:** *Adopt `markdown` / `mistune` / `markdown-it-py`* — rejected: all three are pure Python and would import cleanly into a bundle, but each adds a runtime dependency (plus its transitive closure) to every `.pyz` that stages `html_report`, for CommonMark fidelity no report artifact currently needs. Safety is configuration rather than default — raw-HTML passthrough and URL-scheme filtering have to be pinned per library, and the safe-by-default combination (`markdown` + a sanitizer) is unavailable here: the maintained sanitizer `nh3` is a native Rust extension the bundle doctrine prohibits, and pure-Python `bleach` is deprecated. A dependency also puts committed-bundle bytes at the mercy of upstream output changes on every upgrade. *Delete the HTML path* — rejected: `/age --html` ships it.
- **Consequences:** Report authors stay inside the documented subset; anything outside it degrades to literal text rather than rendering (never raises). Every `.pyz` staging `html_report` stays dependency-free and byte-reproducible. If CommonMark fidelity ever becomes a requirement — externally authored Markdown, or embedded images in reports — this ADR is the decision to revisit, and the pure-Python sanitizer situation is the first thing to re-check.
